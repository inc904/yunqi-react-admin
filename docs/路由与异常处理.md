# 路由与异常处理

## 当前路由策略

项目当前使用 `BrowserRouter + Routes + Route`，属于 React Router 的 Declarative Mode。路由仍保留在 `src/App.tsx`，因为当前页面数量有限，入口一眼可见。

```tsx
<Routes>
  <Route path="/" element={<Navigate to="/dashboard" replace />} />
  <Route path="/dashboard" element={<DashboardPage />} />
  {/* 其它明确业务路由 */}
  <Route path="*" element={<NotFoundPage />} />
</Routes>
```

`replace` 会替换浏览器历史记录，用户在 `/` 自动进入仪表盘后，按后退不会回到一个立刻再次跳转的地址。

## 不同错误的边界

| 场景             | 例子                        | 处理位置                     | 当前/建议 UI                    |
| ---------------- | --------------------------- | ---------------------------- | ------------------------------- |
| 首页跳转         | `/`                         | 路由                         | `Navigate` 到 `/dashboard`      |
| 前端 404         | `/produts`、`/unknown`      | 路由兜底                     | `NotFoundPage`，可返回仪表盘    |
| 权限 403         | 运营人员访问 `/admin-users` | 权限路由守卫                 | `ForbiddenPage`；不能仅隐藏菜单 |
| 接口 404         | 请求的订单 ID 不存在        | API/页面数据状态             | 在详情区域显示“数据不存在”      |
| 接口 500 / 超时  | Mock API 的异常演练         | Axios + `useRequest/usePage` | 保留页面框架，显示错误与重试    |
| React 运行时异常 | 组件渲染时抛错              | React Error Boundary         | 应用级故障页与错误上报          |

前端 404 和 HTTP 404 不同：前者表示 SPA 已加载但没有匹配路由；后者表示服务器没有返回前端入口文件。生产服务器必须将已知的前端路径回退到 `index.html`，同时排除 `/api`，否则刷新 `/products` 时 React 还没启动就会得到服务器 404。

## 当路由增多：迁移到 `src/app/routes.tsx`

当 `App.tsx` 的路由声明成为难以阅读的长列表，或开始出现路由守卫、嵌套路由、懒加载时，把**路由表**迁移到 `src/app/routes.tsx`。这只是文件职责调整，仍然是 Declarative Mode，并不意味着必须迁移到 `createBrowserRouter`。

### `src/app/routes.tsx` 示例

```tsx
import { Navigate, Route, Routes } from 'react-router-dom'
import { NotFoundPage } from './NotFoundPage'
import { DashboardPage } from '../features/dashboard/DashboardPage'
import { ProductsPage } from '../features/products/ProductsPage'
import { OrdersPage } from '../features/orders/OrdersPage'
import { hasPermission } from '../components/layout/ConsoleLayout'
import type { Auth } from '../types'

type AppRoutesProps = { auth: Auth }

export function AppRoutes({ auth }: AppRoutesProps) {
  return (
    <Routes>
      <Route path="/" element={<Navigate to="/dashboard" replace />} />
      <Route path="/dashboard" element={<DashboardPage />} />
      <Route path="/products" element={<ProductsPage canEdit={hasPermission(auth, 'product:*')} />} />
      <Route path="/orders" element={<OrdersPage canEdit={hasPermission(auth, 'order:*')} />} />
      <Route path="*" element={<NotFoundPage />} />
    </Routes>
  )
}
```

### `App.tsx` 如何使用

```tsx
<ConsoleLayout auth={auth} onLogout={logout}>
  <AppRoutes auth={auth} />
</ConsoleLayout>
```

此时 `App.tsx` 只处理应用启动、身份状态和 Layout；`routes.tsx` 只描述路径与页面的映射；各 `features` 只关心自己的业务 UI。

## 何时考虑 Data Mode

如果页面的数据加载、表单提交、路由级 pending 状态、路由级 Error Boundary 已大量出现，可评估 `createBrowserRouter` 的 Data Mode。它能把 `loader`、`action`、`errorElement` 放在路由定义中；但当前项目已有 Axios 与自定义 Hook，请求层还很轻量，不需要为此立即迁移。

参考：[React Router Modes](https://reactrouter.com/start/modes)、[Error Boundaries](https://reactrouter.com/how-to/error-boundary)。
