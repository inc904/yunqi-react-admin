## BUG-001：除仪表盘外的列表接口成功但页面不渲染数据

| 项目 | 记录 |
| --- | --- |
| 发现日期 | 2026-09-15 |
| 影响范围 | 商品、分类、订单、会员、优惠券、Banner、管理员、角色、操作日志页面 |
| 严重程度 | 高：核心列表全部不可用，但仪表盘正常，容易造成误判 |
| 状态 | 已修复 |

### 现象

- 浏览器 Network 面板中，列表接口返回 `200`，响应体里有真实数组和 `meta` 分页信息。
- 页面没有报错，但表格、Banner 卡片、角色列表等显示为空。
- 仪表盘却可以正确显示指标、趋势和热销商品。

### 定位过程

1. 使用管理员令牌逐一请求所有资源接口，确认 `/products`、`/orders`、`/customers` 等均返回非空数组。
2. 对比接口形状：仪表盘为 `{ data: Overview }`，列表为 `{ data: T[], meta: PaginationMeta }`。
3. 检查 Axios 拦截器和 `useRequest`：拦截器已从 `AxiosResponse` 中取出一次 `.data`，`useRequest` 又取了一次 `.data`。
4. `usePage` 把这个已经是数组的值继续当成 `{ data, meta }` 使用，`数组.data` 是 `undefined`，因此通过 `?? []` 变成了空数组。

### 根因

请求层的“解包边界”没有定义清楚：Axios HTTP 响应层与 Mock API 业务信封层都叫 `data`。单对象接口在两次解包后恰好得到业务对象；分页接口则在第二次解包后丢失了 `meta`，形成了仅列表页暴露的问题。

### 修复

- 在 `src/api.ts` 明确 `ApiEnvelope<T>`，并规定响应拦截器只剥离 AxiosResponse，保留后端 `{ data, meta }` 信封。
- `useRequest<T>` 专门处理单对象接口，只解包一次 `response.data`。
- 新建独立的 `usePage<T>`，保留完整 `PageResult<T>`；页面从 `data.data` 读取数组、从 `data.meta` 读取分页。
- 为请求层和分页 Hook 增加中文教学注释，说明两者不可直接互换的原因。

### 验证

| 验证项 | 结果 |
| --- | --- |
| 9 个列表接口返回数据与总数 | 通过：商品 60、分类 6、订单 260、会员 120、优惠券 8、Banner 2、管理员 2、角色 2、日志 66 |
| TypeScript 检查与 Vite 生产构建 | 通过：`npm run build` |
| 列表组件的读取路径 | 已改为 `PageResult<T>.data` 与 `PageResult<T>.meta` |

### 防复发措施

1. 新接口接入前先写明“页面拿到的对象形状”，不要只根据字段名猜测。
2. 单对象、分页、文件下载等不同响应形态应使用不同 Hook 或显式的适配器。
3. 后续可给 `usePage` 增加单元测试：断言接口返回 `{ data: [item], meta }` 时 `items.length` 为 1 且 `meta.total` 正确。
4. 评审请求封装时，重点检查是否对同一层级的 `data` 重复解包。
